# 测试案例素材中心

当前恢复版已包含四个浏览器工作台。安装依赖 `npm ci`，运行 `npm run dev`，访问 `http://127.0.0.1:3016/`；无需相邻目录的旧工作台服务。新增合同制作见 [CONTRACTS.md](CONTRACTS.md)，静态站点构建见 [ONLINE.md](ONLINE.md)。推荐 Node.js 22.13 或更新版本。原历史源码另有恢复备份，此目录为继续开发的工作副本。

部署到 GitHub Pages 请按 [GITHUB_PAGES.md](GITHUB_PAGES.md) 操作；已包含自动构建发布流程，仓库子路径自动适配。

以下是旧版多进程本机启动器的说明，保留用于历史维护；使用恢复版请按上面的统一入口运行。

双击项目根目录的 `启动素材中心.command`，打开 `http://localhost:3015/`。首页汇总企业证照、财务材料、权属登记三个工作台，并自动启动尚未运行的服务。点击卡片在新标签页进入；每个工作台顶部或侧栏都有“素材中心”返回链接。

保持启动窗口开启。按 Control+C 关闭素材中心时，只停止由这次素材中心新启动的服务；启动前已在运行的服务继续保留。重复双击会打开现有入口，不重复启动。启动错误会显示在卡片上，详细运行日志在 `local_data/`。

## 现有工作台

| 名称 | 目录 | 默认地址 |
|---|---|---|
| 企业证照 | 本目录（浏览器版） | `http://127.0.0.1:3016/certificates/` |
| 财务材料 | `../财务素材工作台` | `http://localhost:3000/` |
| 权属登记 | `../权属登记素材工作台` | `http://localhost:3012/` |

企业证照采用和在线站点一致的 React / SVG 浏览器版，文件由浏览器生成。旧版 Python 生成服务已不再作为入口。财务和权属工作台保持固定端口；端口被其他服务使用时显示提示，不接管或终止该服务。

这次只统一入口与启动方式，不合并三个工作台的业务数据、填写方案或导出目录，不读取原题文件，也不发布公网网站。首页没有跨工作台“最近方案”或整案导出功能。

## 以后增加工作台

在 `workbenches.json` 的 `workbenches` 数组增加一条登记，再重启素材中心即可。界面从登记表生成，不需要复制首页卡片。

- `id`：唯一英文标识，小写字母、数字及短横线。
- `name`、`subtitle`、`description`、`documents`、`outputs`：首页显示内容。
- `directory`：相对于“测试案例”项目的子目录。
- `url`：固定本机入口，保持与独立启动时相同的主机名与端口，以保留浏览器草稿。
- `health_path`、`health_key`、`health_value`：识别对应工作台的只读 JSON 地址及字段。例如静态文件 `public/material-center.json`，内容为 `{"workbench":"new-module"}`。
- `runtime`：`python` 或 `node`。
- `args`：传给运行程序的参数数组，工作目录为上述子目录；不经过 shell。
- `discovery_file`：可选，用于读取 Python 工作台返回的动态本机地址。

Node 工作台参考已有两条登记，使用 `--strictPort`，避免自动换端口造成草稿看似丢失。Python 工作台的健康接口还需返回 `project_root`，与登记目录的绝对路径一致。外部地址不能接入这个本机启动器。

新模块也应加入 `http://localhost:3015/` 返回链接。浏览器编辑器建议在新标签页打开中心，保留编辑中的页面。可能部署到公网的工作台只应在本机运行时展示这个本机链接。

## 开发与验证

使用 Python 3.10 或以上版本运行 `python3 server.py`。启动脚本优先复用本机 Codex 的 Python，这只用于本机入口管理，证照生成不再需要 Python 或其依赖。Node 默认优先复用本机 Codex 运行时，也可用 `MATERIAL_CENTER_NODE` 指定 Node 路径；不自动安装依赖。

运行 `python3 -m unittest discover -s tests -v` 检查服务复用、进程启停、端口冲突、动态端口发现、登记校验及本机启动接口。前端脚本可用 `node --check web/app.js` 检查语法。

总入口只是本地入口服务，不属于任意一个子工作台的 Sites 站点。将来整体部署时需另行确定统一域名、服务端生成环境与访问范围。
